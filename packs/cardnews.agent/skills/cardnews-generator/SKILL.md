# 카드뉴스 생성 (Cardnews Generator)

> 핵심 명제: **카드뉴스는 광고가 아니라 "스크롤을 멈추게 하는 첫 장 + 저장하게 만드는 본문"이다.**
> 마케터 관점: 도달(훅) → 체류(정보 밀도) → 행동(CTA) 순서로 설계한다.

## 1. 구성 규칙

- 총 6~10장. 인스타 카드뉴스 기본 규격은 1080×1350(4:5 세로). 정방형은 사용자가 명시할 때만 쓴다.
- **1장 = Title/훅**: 타깃의 고통/호기심을 1문장으로. 숫자·반전·질문 중 하나를 쓴다. `brand_kit`에 로고가 제공된 경우에만 작게 쓴다.
- **2장 = 공감/문제 확대**: "왜 이게 당신 얘기인가".
- **3~(n-1)장 = 본문**: 카드 1장당 포인트 1개. 헤드라인(굵게, 2줄 이내) + 보조설명 1~2줄.
- **마지막 장 = End/브랜드 클로징**: `brand_kit`/입력 메모리에 제공된 회사 로고, 브랜드명, 짧은 태그라인, 다음 행동 1개, URL/핸들만 쓴다. 제공되지 않은 로고·URL·핸들은 지어내지 않는다. 새 정보·새 수치 금지.
- **빈 카드 금지 — 모든 카드를 채운다.** 1장부터 마지막 장까지 **모든 카드의 title과 본문을 반드시 작성**한다. 특히 **2장(공감/문제 확대)을 절대 비워두지 않는다** — 1장 훅을 받아 "왜 이게 당신 얘기인가"를 한 문장 이상으로 채운다. 채울 내용이 부족하면 카드 수(n)를 줄여 6장까지 내리되, **title이나 본문이 빈 슬롯은 산출물에 남기지 않는다.** 출력 직전 1~n 전 카드가 비지 않았는지 자가 점검한다.
- 카드 우하단에 진행 표시 (예: `3/8`).

## 2. 카피 규칙

- **최종 카드에는 선택된 카피 문구만** 넣는다. 훅의 대안 비교, "~하여 공감대 형성" 같은 작업 노트·의도 설명·메타 서술을 카드(claim/detail)에 절대 넣지 않는다. 대안 비교는 머릿속으로만 하고 결과만 쓴다.
- AI slop 금지: 혁신적/압도적/독보적/최첨단/"단순한 ~가 아니라" 금지.
- 채널 톤: Threads/Instagram은 구어체 한국어(반말 또는 ~요체 중 택1, 카드 세트 내 통일), LinkedIn은 격식체.
- 한 카드에서 전하는 정보는 소리 내어 읽어서 7초 이내 분량.
- 수치는 출처가 있는 것만. 출처는 마지막 본문 카드 하단에 작은 캡션으로 모은다. End 카드에는 출처/수치/새 주장 넣지 않는다.

## 3. 디자인 규칙

- 색은 `brand_kit.key_color`를 우선한다. 브랜드 키트가 없을 때만 `../deck-designer/references/color-palettes.md`에서 **1조합만** 선택한다. SNS는 고대비 네온(21, 24) 또는 그린 계열(25, 26)이 정지율에 유리하지만, 고객 브랜드로 오인될 플랫폼 팔레트를 기본값으로 쓰지 않는다.
- 타이포 최우선: 훅 카드 헤드라인은 카드 폭의 80% 이상을 차지하는 큰 글자. 장식 요소는 1개 이하.
- 아이콘/일러스트가 필요하면 3dicons.co (CC0)에서 소싱하거나 단색 outline SVG로 직접 그린다.
- 4px 그리드, 텍스트/배경 WCAG AA 대비 검증.

## 3.1 이미지 카드 계약

- 카드뉴스는 기본적으로 이미지 슬라이드다. 텍스트만 있는 흰 카드 묶음은 카드뉴스 산출물로 보지 않는다.
- 각 카드의 `details`에는 `이미지:`로 시작하는 이미지 지시를 1개 둔다. 지시는 카드 배경에 필요한 장면, 톤, 피사체, 금지 소재를 포함한다.
- 이미지 지시는 1080×1350 카드 배경에 쓸 수 있는 고해상도 사진/일러스트를 요구한다. 저해상도 썸네일, 작은 소셜 미리보기, 깨지는 크롤러 이미지는 최종 렌더 후보로 쓰지 않는다.
- 렌더링 기본은 full-bleed 이미지 배경 + 40~65% 블랙 오버레이 + 흰색 텍스트다. 이미지 밝기에 따라 오버레이를 조절하되 텍스트 대비가 먼저다.
- 텍스트 안전 영역을 둔다. 상단과 하단은 최소 96px 이상 비우고, 헤드라인/본문/진행 표시는 이미지 가장자리에 붙이지 않는다.
- `source_url`, `license`, `provider`를 image_db에 남긴다. 사용권 검토가 끝나지 않은 이미지는 `source-required` 또는 `review-before-publish`로 표시한다.
- 이미지가 없거나 품질이 부족하면 HTML만 완료로 보지 말고, `NEEDS_IMAGE_SOURCE` 상태로 남긴다.

## 4. 출력 계약

- self-contained HTML 1파일. 카드는 `<section class="card">` 고정 픽셀 규격.
- brand kit가 제공된 경우 CSS 변수와 End 카드 lockup이 그 값을 사용해야 한다. 없으면 로고·URL·핸들을 비운다.
- 카드별 export 가이드 주석 포함 (브라우저 스크린샷 또는 headless capture).
- 함께 출력: 채널별 캡션 텍스트(해시태그 포함), 게시 시간 제안. End 카드는 브랜드 카드로 닫는다.

## 5. QC

- `deck-qc` 스킬로 훅 강도·정보 정확성·카피 톤을 검증받는다. 특히 1장 훅은 대안 2개 이상 만들어 비교 후 선택한다.
