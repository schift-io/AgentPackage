# Payables Management (매입 관리 → 지급 — 매입 세금계산서·청구서→미지급금(AP) 관리)

## Purpose

거래처 매입 세금계산서·청구서·거래명세서를 모아 ① 매입처별 지급 대상 정리
(공급가액·세액·합계) ② 지급 일정·기한 정리 ③ 지급 예정 알람 목록 ④ 지급 완료 체크까지의
**미지급금(AP) 관리본**을 만든다.

`ledger-automation`이 "기간 단위 거래내역 → 장부·세무·경영 리포트"라면, 이 스킬은
"매입 채무 → 지급 대상·일정·완료 추적"이다. 같은 회계 기준(적격증빙·부가세 매입공제)을
그대로 적용하되, 입력은 매입 증빙, 출력은 거래처별 지급 관리대장이다.

## Inputs

- 사용자 한 줄 요청 (예: "이번 달 매입 세금계산서 모아서 지급 일정 정리", "다음 주 지급 예정 알람")
- 매입 자료: 매입 세금계산서(전자/종이) 이미지·PDF, 거래처 청구서, 매입 거래명세서, 계약상 결제조건
- 대상 기간: 월 / 분기 / 지급 예정 구간
- 사업자 유형: 개인사업자 / 법인 (부가세 매입공제 처리 기준)
- 회사 결제 규정·결제조건 기본값 (예: 익월 말 결제, 30일 등 — default 회사 버킷, 있으면)
- 지급 상태 입력 (사람이 표시: 지급 완료/예정/연체)

## 사용 전 intake

한 번에 1~3문항씩 확인한다. 다 모르면 [확인 필요]로 두고 진행한다.

- 사업자 유형 (개인 / 법인)
- 목표 산출물 (매입처별 지급 대상 정리 / 지급 일정표 / 지급 예정 알람 목록 / 지급 완료 추적본)
- 입력 자료 종류와 대상 기간
- 결제조건 기준 (세금계산서 작성일자 기준 / 청구일 기준 / 계약상 결제조건)
- 지급 알람 기준일 (예: 지급예정일 D-3)
- 민감정보 처리 수준 (사업자번호·계좌번호 마스킹 범위)

## Pipeline (단계)

1. **매입 정리** — 매입 세금계산서·청구서·거래명세서를 표준 AP 스키마로 정규화.
   거래처(상호+사업자번호)·작성일자·품목·공급가액·세액·합계를 파싱하고, 매입처별로 묶는다.
2. **지급 일정** — 결제조건(기일)을 적용해 거래마다 지급예정일을 산출한다.
   결제조건이 없으면 [확인 필요]로 두고 임의 확정하지 않는다.
3. **지급 알람** — 지급예정일 기준 알람 규칙(D-3 등)으로 임박·연체 건을 추려 예정 목록을 만든다.
4. **지급 완료 추적** — 지급상태(예정/완료/연체)를 행마다 추적하고, 미지급 잔액을 집계한다.
   완료 여부는 사람이 표시한 값을 따른다.
5. **증빙·공제 점검** — 적격증빙 여부·부가세 매입공제 가부를 거래마다 판단하고,
   세금계산서 발행이 필요한 건은 Bolta 핸드오프로 표시한다.

세부 스키마·알람 규칙·공제 점검·Bolta 핸드오프 기준은 references/payables-fields.md.

## Rules

- **세금계산서 발행은 Bolta API 연동으로만 처리한다. 자체 발행 구현 금지.** 발행이 필요한
  매입/역발행 건은 산출물에 **Bolta 핸드오프**로 표시하고, 이 스킬은 발행을 수행하지 않는다.
- **실제 계좌이체·대금 지급은 사람이 승인·실행한다.** 이 스킬은 지급 대상 정리·일정·알람·완료
  추적까지만 담당한다. 어떤 경우에도 자동 이체·결제 side-effect를 실행하지 않는다.
- 원본에서 확인되는 사실만 적는다. 거래처/사업자번호/금액/일자/세금계산서 작성일자가
  없으면 [확인 필요]로 표시하고 지어내지 않는다.
- 지급예정일은 결제조건(기일)에서 계산한다. 결제조건이 불명확하면 자동 확정하지 말고
  [확인 필요]로 둔다. 임의로 "익월 말" 등을 가정하지 않는다.
- 거래 한 건마다 ① 적격증빙 여부 ② 부가세 매입세액 공제 가부를 판단한다. 부가세 불공제
  항목(접대비·비영업용 승용차·면세·간이/면세사업자 발행분)은 표시한다.
- 같은 매입이 세금계산서·청구서·거래명세서에 중복으로 잡히면 1건으로 합치되, 금액·일자가
  충돌하면 자동 확정하지 말고 검토 필요로 남긴다.
- 지급 상태(예정/완료/연체)는 사람이 표시한 값을 진실로 삼는다. 임의로 완료 처리하지 않는다.
  지급예정일이 지났는데 완료 표시가 없으면 연체로 표시한다.
- 사업자번호·계좌번호 등 민감정보는 끝 4자리만 노출하고 나머지는 마스킹한다.
- 생성물은 **참고용 초안**이다. 공식 회계감사·세무신고를 대체하지 않는다. 지급 실행·신고
  전 담당자/세무대리인 검토가 필요함을 산출물에 남긴다.

## 도구 경계

- 적격증빙·부가세 매입공제 가부 기준은 `accounting-kr-tax-reference` 버킷(schift-rag)을
  먼저 검색하고, 검색된 근거를 공제 판단 문장에 함께 남긴다.
- 회사 결제 규정·결제조건 기본값은 `default` 회사 버킷에서 확인한다. 없으면 [확인 필요]로
  회사 규정 확인을 요청한다.
- 세금계산서 발행/역발행은 **Bolta API 연동**이 담당한다. 이 스킬은 발행 대상만 식별해
  Bolta 핸드오프로 표시한다.
- CSV/엑셀/PDF 파싱, 지급 관리대장·알람 목록 렌더링 같은 산출은 AWP의 document-helper
  노드가 처리한다. 이 스킬은 AP 스키마와 지급 일정·알람 구조·값을 정의한다.
- OCR/문서 파싱 결과가 충돌하면 자동 확정하지 않는다.

## Output Contract

- `format`: html / csv (+ document-helper로 xlsx·pdf 변환)
- 단계별 산출을 {id, title, bullets:[{claim, details[]}]} 구조로 반환한다.
- 매입처별 지급 대상·지급 일정표·알람 목록·완료 추적본의 컬럼/지표는
  references/payables-fields.md를 따른다.
- 발행 필요분은 Bolta 핸드오프로, 지급 실행은 사람 승인으로 명시한다.
- 마지막 섹션은 항상 "지급 전 검수 체크(사람 확인)"로 남긴다.
