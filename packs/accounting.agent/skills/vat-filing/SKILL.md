# VAT Filing (부가세 신고 준비 — 분기 집계→신고서 초안·점검)

## Purpose

분기 매입·매출 거래내역·세금계산서·신용카드·현금영수증을 신고 단위로 집계해
**부가가치세 신고서 초안 + 공제/불공제 점검 + 세무사 전달본**을 만든다. 과세·영세율
매출, 세금계산서·신용카드·현금영수증 매입을 신고서 칸 단위로 모으고, 매입세액
공제/불공제를 항목별로 점검한 뒤, 세무대리인이 바로 검토할 수 있는 묶음으로 낸다.

`ledger-automation`이 "원본 자료 → 표준 거래내역·장부"라면, 이 스킬은 그 표준
거래내역을 **신고 단위로 한 번 더 가공**하는 관계다. 같은 회계 기준(적격증빙·부가세
공제/불공제)을 그대로 쓰되, 입력은 분기 거래내역, 출력은 부가세 신고서 초안과 점검
리스트다.

## Inputs

- 사용자 한 줄 요청 (예: "1기 확정 부가세 신고 준비", "2분기 매입세액 공제 점검")
- 신고 단위 자료: `ledger-automation`이 만든 표준 거래내역 / 매출·매입 세금계산서
  (전자세금계산서 합계표 포함) / 신용카드 매출·매입 내역 / 현금영수증 발행·수취 내역
- 과세기간: 1기 예정(1~3월) / 1기 확정(1~6월) / 2기 예정(7~9월) / 2기 확정(7~12월)
- 사업자 정보: 상호·법인명, 대표자명, 사업자등록번호, 업태/종목/업종코드, 사업장 주소
- 사업자 유형: 일반과세자 (이 스킬 기본) / 간이·면세는 범위 밖으로 표시
- (선택) 예정신고 누락분, 예정고지세액, 대손세액, 환급 계좌

## 사용 전 intake

한 번에 1~3문항씩 확인한다. 다 모르면 [확인 필요]로 두고 진행한다.

- 과세기간(1기/2기 · 예정/확정)과 신고 마감일
- 사업자 유형이 일반과세자가 맞는지 (간이/면세면 양식이 다름 → 범위 밖)
- 입력 자료 종류 (표준 거래내역 / 세금계산서 합계표 / 카드·현금영수증)
- 영세율·예정신고 누락분·대손세액·예정고지 해당 여부
- 환급 발생 시 환급 계좌 신고 필요 여부
- 공식 제출 예정 여부 (세무대리인 전자신고 / 홈택스 직접 신고)

## Pipeline (단계)

1. **신고 단위 집계** — 표준 거래내역·세금계산서·카드·현금영수증을 매출/매입으로 나눠
   신고서 칸(과세·영세율·세금계산서수취·기타공제 등) 단위로 합산한다.
2. **매출세액** — 과세표준(공급가액)과 매출세액을 칸별로 채우고, 영세율·예정신고
   누락분·대손세액 가감을 반영해 합계(9)를 만든다.
3. **매입세액·공제 점검** — 세금계산서 수취분·기타공제를 모으고, **공제받지 못할
   매입세액(16)** 을 항목별로 분리해 차감계(17)를 낸다. 불공제 사유를 줄마다 남긴다.
4. **납부(환급)세액** — 매출세액 − 매입세액에 경감·공제세액·예정고지·가산세를 반영해
   차감 납부/환급 세액(27)을 산출한다. 과세표준 명세(28~32)도 채운다.
5. **세무사 전달본** — 신고서 초안 + 칸별 산출 근거 + 점검 리스트를 한 묶음으로 낸다.

신고서 칸 매핑·집계 규칙·공제/불공제 점검·검수 항목은
references/vat-return-fields.md.

## Rules

- **신고서 작성·전자신고 자체는 홈택스/세무대리인의 몫이다.** 이 스킬은 신고서 **초안
  + 집계 + 점검 리스트**까지만 만든다. 생성물은 **참고용 초안**이며, 신고 전
  세무대리인 검토가 필수임을 산출물에 남긴다. 홈택스 로그인·전자신고 제출 같은
  side-effect는 절대 수행하지 않는다.
- 원본·표준 거래내역에서 확인되는 사실만 신고서 칸에 채운다. 공급가액·세액·거래처·
  사업자번호가 없으면 [확인 필요]로 표시하고 지어내지 않는다.
- 매출은 과세(세금계산서/카드·현금영수증/기타)·영세율을 구분해 칸별로 분리한다.
  매입은 세금계산서 수취분(일반/고정자산)·기타공제·**불공제**를 구분한다.
- 매입세액 공제/불공제 판단은 거래마다 명시하고 근거를 남긴다. 불공제 항목(접대비·
  비영업용 승용차 구입·유지·면세 관련·간이·세금계산서 미수취·사업무관)은 **공제받지
  못할 매입세액(16)** 으로 분리한다. 애매하면 후보 2개 + [확인 필요].
- 세금계산서 합계표 합계와 신고서 칸 합계, 카드·현금영수증 집계가 서로 맞는지 검산한다.
  충돌하면 자동 확정하지 말고 검토 필요로 남긴다.
- 매출세액과 매입세액의 산식(과세표준 × 세율, 합계(9)·차감계(17)·납부세액(27))을 다시
  계산해 보여주고, 원본 합계와 어긋나면 [확인 필요]로 분리한다.
- 사업자등록번호·계좌번호 등 민감정보는 노출을 최소화하고 끝 4자리만 표기한다.
- 간이과세자·면세사업자 신고는 양식이 다르므로 이 스킬 범위 밖임을 명시한다.

## 도구 경계

- 매입세액 공제/불공제 판단 기준은 `accounting-kr-tax-reference` 버킷(schift-rag)을
  먼저 검색하고, 검색된 근거를 점검 문장에 함께 남긴다.
- 신고서 칸 정의·서식 항목은 references/vat-return-fields.md(부가가치세법 시행규칙
  [별지 제21호서식] 일반과세자 부가가치세 신고서, 개정 2019.2.11)를 정본으로 한다.
- 표준 거래내역(매출/매입·공급가액·세액·증빙구분·부가세공제)은 `ledger-automation`
  산출물을 입력으로 받는다. 없으면 먼저 거래내역 표준화를 거치도록 안내한다.
- CSV/엑셀/PDF 파싱·신고서 초안 렌더링·세무사 전달본 병합은 AWP의 document-helper
  노드가 처리한다. 이 스킬은 신고서 칸 값과 점검 구조를 정의한다.

## Output Contract

- `format`: html / csv (+ document-helper로 xlsx·pdf 변환)
- 단계별 산출을 {id, title, bullets:[{claim, details[]}]} 구조로 반환한다.
- 신고서 칸 매핑·집계·점검 항목은 references/vat-return-fields.md를 따른다.
- 마지막 섹션은 항상 "제출 전 검수 체크(사람 확인)"로 남긴다.
