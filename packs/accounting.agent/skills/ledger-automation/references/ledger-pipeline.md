# 장부 자동화 파이프라인 명세 (Room821 자체 정의)

원본 거래 자료를 표준 거래내역으로 정규화 → 계정과목 매핑 → 세무·경영 리포트로
만드는 단계별 스키마·규칙·산출물 명세. 회계 판단 기준은 `accounting-kr-tax-reference`
버킷과 knowledge/kr-accounting-reference.md가 정본이며, 여기서는 데이터 구조와
파이프라인만 정의한다. 회사별 회계정책과 다를 수 있고, 최종 처리는 세무대리인이 확인한다.

---

## 1. 표준 거래내역 스키마

원본 형식(은행 CSV·카드 PDF·엑셀·영수증)이 무엇이든 아래 1행=1거래 스키마로 정규화한다.

| 컬럼 | 설명 | 비고 |
|------|------|------|
| 거래일자 | 거래 발생일 | YYYY-MM-DD, 증빙 일자와 대조 |
| 적요 | 원본 거래 내용/가맹점명 | 원본 문자열 보존 |
| 거래처 | 정규화된 상호 | 사업자번호 있으면 함께 |
| 사업자번호 | 공급처 등록번호 | 적격증빙 판정용, 없으면 [확인 필요] |
| 입금 | 입금액(+) | 입출금 분리 표기 |
| 출금 | 출금액(−) | |
| 공급가액 | 부가세 제외 | 카드·세금계산서에서 분해 |
| 세액 | 부가세 | 면세/불공제 표시 |
| 합계금액 | 공급가액 + 세액 | 검산 |
| 결제수단 | 현금/법인카드/체크카드/계좌이체 (+ 끝 4자리) | 나머지 자리 마스킹 |
| 계정과목 | 매핑 결과 | 분류 근거 함께(거래처/MCC/규칙) |
| 증빙구분 | 세금계산서/계산서/카드매출전표/현금영수증/간이영수증/기타 | 적격 여부 |
| 부가세공제 | 공제/불공제 | 불공제 사유 |
| 출처 | bank_csv / card_pdf / excel / receipt / codef | 중복 병합 추적 |
| 상태 | 확정/검토/[확인 필요] | 충돌·누락 메모 |

### 정규화 규칙

- **중복 병합**: 같은 거래가 은행·카드·영수증에 중복으로 잡히면 (일자±1일, 금액 일치,
  거래처 유사) 1건으로 합치고 `출처`에 합쳐진 소스를 모두 기록한다. 금액·일자가
  충돌하면 병합하지 않고 둘 다 `상태=검토`로 남긴다.
- **부호**: 출금은 음수, 입금은 양수로 통일. 카드 취소·환불은 반대 부호.
- **금액 파싱**: 천단위 구분·통화기호·괄호(−) 정리. 외화는 원화 환산값과 원통화를 함께.
- **마스킹**: 계좌·카드번호는 끝 4자리만, 주민/사업자번호 등은 노출 최소화.

## 2. 계정과목 매핑 우선순위

아래 순서로 매핑하고, 적중한 규칙을 분류 근거로 남긴다. 충돌·미적중은 후보 2개 + [확인 필요].

1. **거래처명 매핑** — 알려진 공급처 → 계정과목 (예: AWS·Notion·Slack → 지급수수료).
2. **MCC(가맹점 업종코드)** — 카드 데이터에 MCC가 있으면 업종 기반 1차 분류.
3. **정규식 규칙** — 적요 문자열 패턴 (예: `택시|KTX|주차` → 여비교통비).
4. **학습 규칙** — 사용자가 과거에 확정한 (거래처→계정과목) 매핑을 우선 재사용.

- "거래처 대상 vs 임직원 대상"이 접대비(불공제)/복리후생비(공제)를 가른다 — 대상 확인이 핵심.
- 매핑 정본은 knowledge/kr-accounting-reference.md "지출유형 → 계정과목 매핑" 표.

## 3. 세무 리포트 산출물

### 3.1 세무용 BS·PL (요약)

- **손익(PL)**: 매출 / 매출원가 / 판관비(계정과목별) / 영업이익 / 영업외 / 당기순이익.
- **재무상태(BS)**: 현금·예금 / 매출채권 / 매입채무 / 미지급금 등 잔액(자료 범위 내 추정).
- 자료가 거래내역만이면 PL 중심으로 만들고, BS는 [확인 필요]로 잔액 출처를 요청한다.

### 3.2 세무사 전달 CSV

- 컬럼: `거래일자, 적요, 거래처, 사업자번호, 공급가액, 세액, 합계금액, 계정과목,
  증빙구분, 부가세공제, 비고`.
- 세무사가 바로 전표 입력할 수 있게 1행=1거래, 부가세 공제/불공제·증빙구분을 명시한다.
- 충돌·미확정 거래는 `비고`에 [확인 필요] 사유를 적어 분리한다.

### 3.3 종합소득세 준비 체크리스트 (개인사업자·프리랜서)

- [ ] 사업소득 수입금액 집계 (현금영수증·세금계산서 매출 대조)
- [ ] 필요경비 계정과목별 합계 + 적격증빙 확보 현황
- [ ] 3만 원 초과 비적격증빙 → 증빙불비 가산세 위험 목록
- [ ] 원천징수(3.3% 외주·인건비) 지급명세서 대조
- [ ] 부가세 신고분과 소득세 수입금액 정합성
- [ ] 공제·감면 항목(노란우산·연금 등) 누락 확인 → 세무대리인 검토

## 4. 경영 리포트 산출물

- **월별 현금흐름**: 월 단위 유입·유출·순현금흐름, 누적 잔액 추이.
- **Cash burn / runway**: 월 평균 순유출, 현재 현금 ÷ burn = 예상 runway(개월).
- **카드별 분석**: 카드(끝 4자리)별 지출 합계·계정과목 구성·전월 대비 증감.
- **계정과목별 집계**: 기간 내 계정과목별 지출 Top-N + 비중.
- **요약 대시보드**: 위 지표를 한 화면 요약(총수입/총지출/순현금/burn/상위 계정).

## 5. 자동 수집 (CODEF BYOK) — 선택

- 자동 수집은 **BYOK** 원칙. 사용자가 직접 발급한 CODEF Client ID/Secret만 사용한다.
- 키 값은 대화/로그/산출물에 노출하지 않는다. 저장은 로컬 한정(예: OS 키체인 또는
  `~/.config` 하위 0o600 파일)으로, 외부 전송하지 않는다.
- 금융기관 조회·간편인증·로그인 등 side-effect는 **사용자 명시 승인 없이 실행하지 않는다.**
- 수집된 원시 데이터는 §1 표준 거래내역 스키마로 정규화한 뒤 파이프라인에 합류시킨다.
- BYOK 미설정 시 자동 수집 단계는 건너뛰고, 사용자가 올린 파일만으로 진행한다.
