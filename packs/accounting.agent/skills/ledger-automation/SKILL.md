# Ledger Automation (장부 자동화 — 거래내역→장부·리포트)

## Purpose

카드명세서 PDF·은행 CSV·엑셀·영수증/세금계산서 이미지·PDF를 **표준 거래내역**으로
정리하고, 계정과목을 자동 매핑한 뒤 세무용(BS·PL, 세무사 전달 CSV, 종합소득세 준비
체크리스트)과 경영용(현금흐름·cash burn·카드별 분석) 리포트를 한 묶음으로 만든다.

`expense-evidence`가 "건별 증빙 → 결재용 지출결의서"라면, 이 스킬은
"기간 단위 거래내역 → 장부·세무·경영 리포트"다. 같은 회계 기준(적격증빙·계정과목·
부가세 매입공제)을 그대로 적용하되, 입력은 다건 명세, 출력은 집계 리포트다.

## Inputs

- 사용자 한 줄 요청 (예: "3월 카드명세서 정리해서 세무사 전달용 CSV", "2분기 현금흐름")
- 거래 자료: 은행 입출금 CSV, 카드 이용내역 PDF/엑셀, 영수증·세금계산서 이미지/PDF,
  계좌이체 내역
- 대상 기간: 월 / 분기 / 연도
- 사업자 유형: 개인사업자 / 법인 / 프리랜서 / 복수 사업장 (산출물 분기 기준)
- 회사 계정과목 체계·내부 규정 (default 회사 버킷, 있으면)
- (선택) 자동 수집: 사용자가 직접 발급한 CODEF Client ID/Secret (BYOK)

## 사용 전 intake

한 번에 1~3문항씩 확인한다. 다 모르면 [확인 필요]로 두고 진행한다.

- 사업자 유형 (개인 / 법인 / 프리랜서 / 복수 사업장)
- 목표 산출물 (표준 거래내역 / 계정과목 분류 / 세무사 전달 CSV / BS·PL /
  현금흐름·경영 리포트 / 종소세 체크리스트)
- 입력 자료 종류와 대상 기간
- 민감정보 처리 수준 (계좌·카드번호 마스킹 범위)
- 공식 제출 예정 여부 (세무사 검토 / 외감 대상 법인 여부)

## Pipeline (단계)

1. **표준화** — 원본(은행 CSV·카드 PDF·엑셀·영수증)을 표준 거래내역 스키마로 정규화.
   중복 제거, 통화·부호(입금+/출금-) 정리, 일자·금액 파싱.
2. **분류** — 거래처명 → MCC → 정규식 → 학습 규칙 우선순위로 계정과목 매핑.
   적격증빙 여부·부가세 공제/불공제를 거래마다 판단.
3. **세무 리포트** — 세무용 BS·PL, 세무사 전달 CSV, 종합소득세 준비 체크리스트.
4. **경영 리포트** — 월별/계정과목별 현금흐름, cash burn, 카드별 분석, 요약 대시보드.
5. **(선택) 자동 수집** — BYOK CODEF 키로 홈택스·은행·카드 수집 흐름 연결.
   조회·로그인 등 side-effect는 사용자 명시 승인 없이 실행하지 않는다.

세부 스키마·매핑 규칙·리포트 명세·BYOK 보안은 references/ledger-pipeline.md.

## Rules

- 원본에서 확인되는 사실만 적는다. 거래처/사업자번호/금액/일자/승인번호가 없으면
  [확인 필요]로 표시하고 지어내지 않는다.
- 거래 한 건마다 ① 계정과목 ② 적격증빙 여부 ③ 부가세 매입세액 공제 여부를 판단한다.
  분류 근거(거래처/MCC/규칙)를 함께 남긴다. 애매하면 후보 2개 + [확인 필요].
- 적격증빙(세금계산서·계산서·카드매출전표·현금영수증)과 비적격을 구분한다. 3만 원
  초과(접대비 3만 원, 경조사비 20만 원 초과)에 적격증빙이 없으면 증빙불비 가산세 위험으로 표시.
- 부가세 불공제 항목(접대비·비영업용 승용차·면세·간이/면세사업자 발행분)은 표시한다.
- 같은 거래가 은행·카드·영수증에 중복으로 잡히면 1건으로 합치되, 금액·일자가 충돌하면
  자동 확정하지 말고 검토 필요로 남긴다.
- 계좌·카드번호 등 민감정보는 끝 4자리만 노출하고 나머지는 마스킹한다.
- 자동 수집(CODEF)은 BYOK. 사용자가 직접 발급한 키만 쓰고 값을 대화에 노출하지 않는다.
  금융기관 조회·간편인증·로그인 같은 side-effect는 명시 승인 후에만 실행한다.
- 생성물은 **참고용 초안**이다. 공식 회계감사·세무신고를 대체하지 않는다. 신고/제출
  전 세무대리인 검토, 외감 대상 법인은 공인회계사 감사가 필요함을 산출물에 남긴다.

## 도구 경계

- 적격증빙·계정과목 매핑·부가세 공제/불공제 기준은 `accounting-kr-tax-reference`
  버킷(schift-rag)을 먼저 검색하고, 검색된 근거를 분류 문장에 함께 남긴다.
- 회사 계정과목 체계·내부 규정은 `default` 회사 버킷에서 확인한다. 없으면 일반 회계
  기준 + [확인 필요]로 회사 규정 확인을 요청한다.
- CSV/엑셀/PDF 파싱, BS·PL·CSV 렌더링, PDF 병합 같은 산출은 AWP의 document-helper
  노드가 처리한다. 이 스킬은 표준 거래내역과 리포트 구조·값을 정의한다.
- OCR/문서 파싱 결과가 충돌하면 자동 확정하지 않는다.

## Output Contract

- `format`: html / csv (+ document-helper로 xlsx·pdf 변환)
- 단계별 산출을 {id, title, bullets:[{claim, details[]}]} 구조로 반환한다.
- 표준 거래내역·계정과목 매핑·리포트의 컬럼/지표는 references/ledger-pipeline.md를 따른다.
- 마지막 섹션은 항상 "제출 전 검수 체크(사람 확인)"로 남긴다.
