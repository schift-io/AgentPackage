# Closing Checklist (월마감·세무 캘린더 — 마감 관제·기한 알람)

## Purpose

월/분기 마감 시점에 ① **마감 체크리스트**(미분류 거래·누락 증빙·미수미지급
미정리·가산세 위험·계정 미마감)를 영역별로 점검하고, ② **세무·4대보험 신고 기한
캘린더**(다가오는 기한 + 준비물)를 만든다.

`ledger-automation`이 "거래내역→장부·리포트"를 만든다면, 이 스킬은 그
산출물들(ledger·expense·vat·withholding·payables·receivables)이 마감 시점에
**빠짐없이 정리됐는지 교차 점검하는 "마감 관제"** 역할이다. 직접 분개·전기·신고를
하지 않고, "무엇이 비었는지 + 언제까지 무엇을 해야 하는지"만 본다.

## Inputs

- 사용자 한 줄 요청 (예: "3월 마감 체크해줘", "이번 달 신고 기한 뭐 남았어")
- 마감 대상 기간: 월 / 분기 / 연도 결산
- 다른 스킬 산출물(있으면): 표준 거래내역·계정과목 분류(ledger), 지출결의·증빙
  목록(expense), 부가세 집계(vat), 원천세·지급명세(withholding), 미지급(payables),
  미수(receivables)
- 사업자 유형: 개인사업자 / 법인(결산월) / 프리랜서 / 간이과세자 / 복수 사업장
- 원천세 반기납부 특례 대상 여부, 4대보험 신고 주기
- 기준일(today) — 다가오는 기한 산정용

## 사용 전 intake

한 번에 1~3문항씩 확인한다. 다 모르면 [확인 필요]로 두고 진행한다.

- 사업자 유형 + 법인이면 결산월 (12월 결산 / 그 외)
- 과세 유형 (일반과세 / 간이과세 / 면세)
- 마감 대상 기간과 산출물 (마감 체크리스트 / 기한 캘린더 / 둘 다)
- 원천세 반기납부 특례 적용 여부, 4대보험 신고 주기
- 점검에 쓸 입력 산출물이 이미 있는지, 없으면 어느 영역이 비었는지

## Pipeline (단계)

1. **수집** — 점검 대상 산출물(ledger·expense·vat·withholding·payables·
   receivables)을 모은다. 없는 영역은 "미산출"로 표시하고 그 자체를 마감 리스크로 본다.
2. **교차 점검** — 영역별 체크리스트(거래/증빙/AR/AP/급여·원천/세무)를 돌려
   미분류·누락·미정리·가산세 위험·계정 미마감 항목을 추려낸다. 영역별 근거를 남긴다.
3. **기한 캘린더** — 기준일 기준으로 다가오는 신고·납부 기한을 정렬하고, 각 기한의
   준비물을 붙인다. 정확 일자·공휴일 이동은 [확인 필요] + 홈택스 확인 권고.
4. **알람 요약** — D-day 임박 기한 + 미완료 체크 항목을 한 화면 요약으로 묶는다.

세부 기한·준비물·체크리스트 항목은 references/closing-calendar.md.

## Rules

- **절대 경계: 실제 마감·전기·신고는 담당자/세무대리인이 한다.** 이 스킬은 **점검
  리스트와 기한 알람까지만** 만든다. 분개 확정·장부 마감·전자신고 제출을 대신 수행하지
  않는다. 산출물 마지막에 "마감 확정 전 사람 확인" 문구를 반드시 남긴다.
- 신고·납부 기한은 **공휴일·말일·연도별 변동에 따라 이동**한다. 캘린더의 날짜는
  일반론이며, **정확 일자는 항상 [확인 필요] + 홈택스/위택스 확인을 권고**한다.
  스킬이 단정한 확정 일자를 제시하지 않는다.
- 점검은 입력 산출물에서 확인되는 사실만 적는다. 산출물이 없는 영역은 "미확인/미산출"로
  표시하고, 비어 있다는 것을 가리지 않는다. 임의로 "정상"으로 처리하지 않는다.
- 미분류 거래·누락 증빙·미정리 미수미지급·미마감 계정은 **건수와 금액(있으면)**을 함께
  보여 마감 영향도를 가늠하게 한다. 금액이 없으면 건수만, 둘 다 없으면 [확인 필요].
- 가산세 위험(3만 원 초과 적격증빙 누락, 신고기한 임박·경과 등)은 "위험" 라벨로 분리
  표시하되, 가산세 금액을 단정 계산하지 않는다(세무대리인 판단).
- 반기납부 특례·간이과세·결산월 등 조건에 따라 기한이 달라지는 항목은 조건을 함께
  적고, 해당 여부가 불명확하면 [확인 필요].
- 이 스킬은 다른 스킬 산출물을 **교차 점검**할 뿐, 그 안의 분류·세액을 재계산해 덮어쓰지
  않는다. 충돌·이상은 "검토 필요"로 남긴다.

## 도구 경계

- 신고 기한·준비물·계정 마감 기준은 references/closing-calendar.md를 1차 근거로
  쓰고, 세부 회계 판단(적격증빙·공제 기준)은 `accounting-kr-tax-reference`
  버킷(schift-rag)을 검색해 근거를 남긴다.
- 회사 결산 정책·마감 내부 규정은 `default` 회사 버킷에서 확인한다. 없으면 일반 기준
  + [확인 필요]로 회사 규정 확인을 요청한다.
- 체크리스트·캘린더 표 렌더링, xlsx/pdf 변환은 AWP의 document-helper 노드가 처리한다.
  이 스킬은 점검 항목·기한·준비물의 구조와 값을 정의한다.
- 실제 기한의 확정 일자 조회(공휴일 이동 반영)는 홈택스/위택스 등 외부 확인 영역으로
  넘긴다. 스킬은 일반론 + [확인 필요]까지만 책임진다.

## Output Contract

- `format`: html (+ document-helper로 xlsx·pdf 변환)
- 산출을 {id, title, bullets:[{claim, details[]}]} 구조로 반환한다.
- 두 블록을 구성한다:
  - **마감 체크리스트** — 영역별(거래/증빙/AR/AP/급여·원천/세무) 체크박스 항목 +
    미완료 건수·금액 + 가산세 "위험" 라벨.
  - **세무·4대보험 기한 캘린더** — 다가오는 기한(D-day 정렬) + 준비물 + 정확
    일자·공휴일 이동 [확인 필요].
- 체크 항목·기한·준비물 목록은 references/closing-calendar.md를 따른다.
- 마지막 섹션은 항상 **"검수·기한 알람(사람 확인) — 마감 확정 전 담당자/세무대리인
  검토 필요"**로 남긴다.
