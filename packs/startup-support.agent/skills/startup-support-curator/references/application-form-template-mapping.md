# 공고별 신청서 양식 매핑 가이드

이 레퍼런스는 startup-support APM이 **공고별 신청서 양식**을 입력으로 받았을 때,
양식의 구조와 항목명을 그대로 따라 제출용 초안을 만드는 방법을 정리한다.

## 1. 입력: 공고별 신청서 양식

APM은 다음 두 가지 형태의 양식을 입력으로 받을 수 있다.

- `application_form_template`: 공고 첨부 파일(PDF/HWPX/TXT)에서 추출한 양식 원문 또는 구조 요약
- `company_profile_sources`: 회사 메타정보를 담은 RAG 소스(회사 소개서, IR, 기존 사업계획서, 증빙 목록 등)

양식이 제공되면 **PSST(Problem-Solution-Scale-up-Team)** 구조보다 양식의 항목명과 순서를 우선한다.

## 2. 양식 해석 원칙

1. **신청서(앞부분)와 사업계획서(본문)를 분리**한다.
2. **신청서 필드**는 회사 메타정보(RAG)로 채운다. 개인정보(주민번호, 상세 주소, 서명 이미지)는 제외한다.
3. **사업계획서 본문**은 양식에 나온 섹션 번호/제목을 그대로 사용한다.
4. **양식의 안내 문구**는 삭제하고, 검정색 제출체 문장으로 바꾼다.
5. **양식의 표 구조**는 HTML `<table>`로 유지한다. 행 추가는 가능하나, 양식의 필수 열은 유지한다.
6. **증빙서류 목록**은 양식에 명시된 구분(자격요건/실적/가점)과 서류명을 그대로 체크리스트로 옮긴다.

## 3. 회사 메타정보 필드 (RAG로 채움)

| 대표자명 | 회사 프로필 기본정보 |  |

## 4. S-CUBE 양식 예시 매핑

아래는 `2026년 연세대학교 캠퍼스타운 에스큐브 입주기업 추가모집 신청서` 양식을 APM 출력에 매핑한 예시다.

> **주의:** S-CUBE 양식은 매핑 예시일 뿐이다. 다른 양식이나 다른 회사에서는
> 해당 양식의 섹션/항목명과 회사 프로필(RAG)을 우선하며, S-CUBE에서 나온
> `ISO 27001`, `5개사 PoC`, `온프레미스 요구 엔터프라이즈` 같은 구체 예시를
> 다른 회사에 맞지 않게 강제 적용하지 않는다.

### 4-1. 신청서(붙임1) 구조

```
[붙임 1] 입주신청서 및 사업계획서

2026년 연세대학교 캠퍼스타운 에스큐브 입주기업 추가모집 신청서
- 대표자명 / 생년월일 / 현재 직업 / 연락처 / 이메일
- 창업 아이템명
- 기업(팀)명 / 사업자등록번호 / 창업여부 / 창업일
- 신청 구분 / 교내창업 유형
- AI 기반 기업 여부 / 기술 분야
- 매출액(2025) / 투자유치액(누적) / 고용인원(2026) / 글로벌진출성과(2025)
- 지식재산권 / 타지원사업실적
- 기업(팀) 인력 구성표
- 입주 모집 구분 / 전용실 신청 인원수
- 신청일 / 대표자 서명
```

### 4-2. 사업계획서 본문 구조

```
□ 창업아이템 개요(요약) — 1page 이내
  - 명칭 / 범주
  - 아이템 개요(제품·서비스 개요, 핵심 기능·성능, 고객 제공 혜택)
  - 배경 및 필요성(개발 필요성, 해결방안, 목표시장, 요구사항)
  - 현황 및 구체화 방안(준비상황, 협약기간 산출물, 역량 활용 계획)
  - 목표시장 및 사업화 전략(수익화 모델, 시장 확보 전략, 차별성/경쟁력)
  - 이미지(참고 사진/설계도)

1. 문제인식 (Problem)
  1-1. 창업아이템의 개발동기
  1-2. 창업아이템의 목적(필요성)

2. 실현가능성 (Solution)
  2-1. 창업아이템의 개발·사업화 전략
      - 비즈니스 모델, 구현정도, 제작 소요기간 및 방법, 추진일정
      - <사업 추진일정> 표
  2-2. 창업아이템의 시장분석 및 경쟁력 확복방안
      - 대체재(경쟁사) 대비 우위요소, 차별화 전략

3. 성장전략 (Scale-up)
  3-1. 자금소요 및 조달계획
      - 사업비 사용계획 (3,000만원 VAT 제외 기준)
      - <사업화자금 집행계획> 표
  3-2. 시장진입 및 성과창출 전략
      3-2-1. 내수시장 확보 방안
      3-2-2. 해외시장 진출 방안

4. 팀 구성 (Team)
  4-1. 대표자 및 팀원의 보유역량
      - 대표자 현황 및 역량
      - 팀원현황 및 역량
      - 추가 인력 고용계획
      - 업무파트너(협력기업 등) 현황 및 역량

증빙서류
  - 자격요건 증빙서류(공통/창업기업/해당자)
  - 실적 증빙서류(해당자)
  - 가점항목 증빙서류(해당자)
```

### 4-3. S-CUBE → APM 섹션 매핑

| S-CUBE 양식 절 | APM 기존 절 | 처리 방침 |
| --- | --- | --- |
| 신청서(앞부분) | 내 조건 요약 | 회사 메타정보를 양식 필드에 채운다. 큐레이션은 별도 "공고·양식 정보" 절로 분리. |
| 창업아이템 개요(요약) | 5-0 사업개요 요약 | 양식의 4개 항목(명칭/범주/개요/배경/현황/목표시장/이미지)을 그대로 따른다. |
| 1. 문제인식 | 5-1 문제인식 | 1-1 개발동기, 1-2 목적(필요성)으로 나눈다. |
| 2. 실현가능성 | 5-2 실현가능성 | 2-1 개발·사업화 전략, 2-2 시장분석 및 경쟁력 확복방안으로 나눈다. |
| 3. 성장전략 | 5-3 성장전략 | 3-1 자금소요 및 조달계획, 3-2 시장진입 및 성과창출 전략(3-2-1/3-2-2)으로 나눈다. |
| 4. 팀 구성 | 5-4 팀 구성 및 증빙 | 4-1 대표자 및 팀원의 보유역량으로 통일. |
| 증빙서류 | 6. 제출 전 확인사항 | 양식의 증빙서류 목록을 그대로 체크리스트로 옮긴다. |

### 4-4. S-CUBE 작성 시 주의사항

1. **회사 프로필(RAG)에 있는 수치/용어는 그대로 사용**한다. 예: 회사 프로필에 `2개사 구축`, `5개사 PoC`, `ISO 27001 인증`, `온프레미스 요구 엔터프라이즈`가 명시되어 있을 때만 원문 그대로 옮기고, 없는 항목은 일반화하지 않는다.
2. **제공되지 않은 수치는 추정/합산하지 않는다**. 예: `PILOT(25팀) + ADOPTION(25팀)`을 `50개사`로 합산하지 말고, 원문 패키지명과 구성만 기술하거나 `고객사와 파일럿 목표는 영업 파이프라인과 근거 자료 확인 후 확정한다`로 둔다.
3. **보안 인증 비목은 회사 프로필에 있을 때만 원문 용어를 그대로 쓴다**. 회사 프로필에 `ISO 27001 인증 취득 1,500만원`이 명시되어 있으면 비목명, 산출근거, 본문 서술 모두 해당 원문을 사용하고 `보안 인증`처럼 일반화하지 않는다. 회사 프로필에 보안 인증이 없으면 `ISO 27001`이나 `보안 인증 취득` 같은 계획을 추가하지 않는다.
4. **역할/경력에 인원 수를 덧붙이지 않는다**. 예: `개발 3년 경험`은 `AI/소프트웨어 개발 총괄` 등으로 표현하되, `개발 3`, `기획/영업 1` 같은 역할별 인원 배분은 하지 않는다.

**비목 표기 예시**

| 항목 | 잘못된 표기 | 올바른 표기 |
| --- | --- | --- |
| 비목명 | `보안 인증 취득` | `ISO 27001 인증 취득` |
| 산출근거 | `보안 인증 비용` | `ISO 27001 인증 비용` |
| 본문 서술 | `주요 비용은 보안 인증 취득과 서버 운영비이다.` | `주요 비용은 ISO 27001 인증 취득과 서버 운영비이다.` |

## 5. 평가자 중심 문체 (제출체)

양식이 주어지면 APM의 역할은 "창업자의 옆자리 PM"에서 **"제출 서류를 정리하는 담당자"**로 전환된다.

### 5-1. 허용 문장 형태

- 선언형: `Schift는 기업 AX를 위한 AI 메모리 서비스이다.`
- 능동형: `자료 반입 → 정제·권한 → 답변·검토 → 운영 전환 단계로 처리한다.`
- 근거 붙임: `겐츠베이커리와의 PoC는 회사 자료(RAG)에 따른 실증 근거이다.`
- 확인 필요: `ISO 27001 인증 취득 비용은 제출 전 견적서 확인이 필요하다.`

### 5-2. 금지 문장 형태

- 조력자 말투: `오늘 의사결정을 도와드리겠습니다`, `확인이 필요해 보입니다`
- 질문형: `온프레미스 선호도가 있나요?` → `보안/배포 요구사항은 제출 전 확인한다.`
- 추측형: `아마도 ~일 것이다`, `추정하기로는 ~`
- 보고체: `검토했습니다`, `생각합니다`, `분석한 결과 ~`

### 5-3. 고정 표현

| 상황 | 제출체 표현 |
| --- | --- |
| 근거 없는 수치/성과 | `제출 전 확인` / `회사 자료 확인 후 확정` |
| 보안/배포 | `보안/배포 요구사항은 제출 전 확인한다.` |
| 예산/인력 | `지원금 활용 세부 산정이 필요하다. 현재 임직원은 3명이며 직묳별 구성과 채용 계획은 제출 전 확인 필요하다.` |
| 고객/파일럿 | `고객사와 파일럿 목표는 영업 파이프라인과 근거 자료 확인 후 확정한다.` |
| 시장/수요 | `시장/수요 규모와 성장률은 공신력 있는 자료로 제출 전 확인 필요하다.` |

## 6. 출력 구조

양식이 주어졌을 때 최종 HTML 아티팩트는 아래 순서로 구성한다.

1. **공고·양식 정보**: 사업명, 기관, 모집 기간, 공식 링크, 양식 출처. (기존 "공고 후보/적합도 판단"은 간략화)
2. **신청서 초안**: 양식 필드를 채운 HTML table. 민감정보는 마스킹 또는 `[제출 전 확인]` 처리.
3. **사업계획서 초안**: 양식의 섹션 제목을 그대로 사용. 각 절에 표/도식 초안 포함.
4. **증빙서류 체크리스트**: 양식의 증빙 목록을 그대로 옮기고 보유/미확인 상태 표기.
5. **제출 전 확인사항**: 누락 자료, 미확정 수치, 사람 검토 항목.

## 7. HTML 계층 및 서식 규칙

양식 기반 초안은 심사자가 **한 눈에 구조를 파악**할 수 있어야 한다. 문단 나열 대신 계층과 리스트를 적극 사용한다.

### 7-1. 제목 계층

| 양식 수준 | HTML 태그 | 예시 |
| --- | --- | --- |
| 최상위 절 | `<h2>` | 공고·양식 정보, 신청서 초안, 사업계획서 초안, 증빙서류 체크리스트, 제출 전 확인사항 |
| 사업계획서 1차 절 | `<h3>` | `□ 창업아이템 개요(요약)`, `1. 문제인식 (Problem)`, `2. 실현가능성 (Solution)` 등 |
| 사업계획서 2차 절 | `<h4>` | `1-1. 창업아이템의 개발동기`, `2-1. 창업아이템의 개발·사업화 전략`, `3-2. 시장진입 및 성과창출 전략` 등 |
| 사업계획서 3차 절 | `<h5>` | `3-2-1. 내수시장 확보 방안`, `3-2-2. 해외시장 진출 방안` |
| 세부 항목군 | `<h6>` | 대표자 현황, 팀원현황, 추가 인력 고용계획, 업무파트너 현황 |

### 7-2. 본문 서식

- **여러 항목이 나염될 때는 `<ul>`/`<li>` 또는 `<ol>`/`<li>`를 사용**한다. `<p><strong>레이블:</strong> 내용</p>`를 여러 개 붙이는 것은 지양한다.
- **창업아이템 개요의 6개 항목**(명칭/범주, 아이템 개요, 배경 및 필요성, 현황 및 구체화 방안, 목표시장 및 사업화 전략, 이미지)은 `<ol>`로 번호를 매기거나, 각 항목을 `<h4>`로 분리한다.
- **문제인식/실현가능성/성장전략/팀 구성**의 각 하위 절 안에서는 핵심 근거를 bullet/numbered list로 정리한다.
- **일정, 예산, 인력 구성, 증빙 목록**은 반드시 HTML `<table>`로 작성한다.
- **도식 초안**은 `<pre>` 안에 `[도식 초안: 제목]` 라벨과 ASCII/유니코드 구조를 남긴다.

### 7-3. 좋은 예시 vs 나쁜 예시

**나쁜 예시** — 항목이 `<p>`+`<strong>`로만 나염됨

```html
<h4>2. 아이템 개요</h4>
<p><strong>제품·서비스 개요:</strong> ...</p>
<p><strong>사용 용도·사양·가격:</strong> ...</p>
<p><strong>핵심 기능·성능:</strong> ...</p>
```

**좋은 예시** — 계층과 리스트로 정리

```html
<h4>2. 아이템 개요</h4>
<ol>
  <li><strong>제품·서비스 개요:</strong> HWP/드라이브 등 기업 내 문서 연결 및 데이터화, 구축된 데이터 기반 간편 파이프라인 실행 런타임 제공</li>
  <li><strong>사용 용도·사양·가격:</strong> 기업 AX의 문서 관리 및 AI 활용을 위한 SaaS. 기본 요금제 구독 + AI 사용량 기반 과금</li>
  <li><strong>핵심 기능·성능:</strong> 파이프라인/데이터/서버/운영/비용관리 통일</li>
  <li><strong>고객 제공 혜택:</strong> 기존 구축형 RAG 대비 낮은 진입 장벽</li>
</ol>
```

### 7-4. S-CUBE 섹션별 서식 매핑

| S-CUBE 양식 절 | 권장 서식 |
| --- | --- |
| 창업아이템 개요(요약) | 6개 항목을 `<ol>` 또는 `<h4>`+`<p>`/`<ul>`로 분리. 이미지는 `<pre>` 도식 초안 |
| 1-1 개발동기 | 배경·문제를 `<ul>`로 2~3개 정리 |
| 1-2 목적(필요성) | 해결 방안을 `<ul>`/`<ol>`로 정리 |
| 2-1 개발·사업화 전략 | 비즈니스 모델·구현정도·방법은 `<ul>`, 추진일정은 `<table>` |
| 2-2 시장분석 및 경쟁력 | 차별화 요소를 `<ul>` 또는 비교 `<table>` |
| 3-1 자금소요 및 조달계획 | `<사업화자금 집행계획>`은 무조건 `<table>` |
| 3-2-1/3-2-2 시장진입 | 내수/해외 전략을 `<ul>`로 정리 |
| 4-1 대표자 및 팀원 보유역량 | 팀원현황/추가 인력/업무파트너는 각각 `<table>` |
| 증빙서류 | `<table>` (구분/서류명/상태) |

## 8. QC 추가 항목

양식이 주어진 경우 아래도 함께 검사한다.

- 신청서 필드 중 회사 메타정보가 `company_profile_sources`에 없는 경우 `[확인 필요]`로 표기했는가?
- 사업계획서 본문이 양식의 섹션 제목과 순서를 따르는가?
- 말투가 평가자 중심 제출체인가? (조력자 말투, 질문형, 보고체 금지)
- 양식의 안내 문구(파란색 글씨)가 남아 있지 않은가?
- 증빙서류 목록이 양식과 일치하는가?
- 회사 프로필에 없는 고객 수/파일럿 수를 새로 만들지 않았는가?
- `ISO 27001` 같은 원문 인증명을 `보안 인증`으로 일반화하지 않았는가?
- 역할별 인원 배분(`개발 1`, `기획/영업 1` 등)을 추정하지 않았는가?
- 제목 계층(`<h2>` → `<h3>` → `<h4>` → `<h5>`)이 양식의 섹션 깊이와 일치하는가?
- 본문 항목들이 `<p>`+`<strong>` 나열 대신 `<ul>`/`<ol>`/`<table>`로 구조화되어 있는가?
