# 지원사업 APM 금지 예시어 Canonical List

이 문서는 startup-support APM의 최종 산출물에 쓰이지 않는 **근거 없는 수치, 성과,
보안/배포 주장, 시장 일반론, 잘못된 APM 확장**의 canonical list다.
`apm.yml`의 `forbidden_patterns`, `rewrite_patterns`, `artifact_quality_algorithm`과
`agent.md`, `SKILL.md`는 이 목록을 참조한다.

## 1. 원칙

- **확인 필요 자체는 금지하지 않는다.** `제출 전 확인`, `확인 필요`, `근거 자료 확인 후
  확정` 등은 이 APM의 정상적인 QC 표현이다.
- **금지 대상은 근거 없는 구체 수치/주장/예시어다.** 사용자 입력이나 공식 공고에
  근거가 없는 숫자, 인증, 고객 수, 채용 인원, 성능 개선 claim을 막는다.
- **원문 예시어는 카테고리로 정규화한다.** 사용자가 근거 없음으로 준 예시어를 본문에서
  반복하지 않고, 아래 `정규화 카테고리`로만 표현한다.
- **회사 프로필(RAG)에 명시된 인증/비목명은 예외다.** 예를 들어 회사 자료에
  `ISO 27001 인증 취득 1,500만원`이라고 적혀 있으면 비목명/산출근거에 그대로 쓰되,
  `보안 인증`처럼 일반화하지 않는다.
- **S-CUBE/Room821 예시는 다른 회사에 강제 적용하지 않는다.** ISO 27001, 5개사 PoC,
  RAG/OCR 워크플로, Schift 등 S-CUBE에서 나온 구체 예시를 사용자 회사에 맞지 않게
  복사하지 않는다.
- **회사 프로필에 기재된 고객/파일럿 수는 원문 형태를 보존한다.** 예: `파일럿 고객: 2개 물류사`
  가 있으면 `2개 물류사`로 쓰고, forbidden regex에 걸리는 형태인 `파일럿 고객 2개사`로
  재조합하지 않는다.
- **보안 인증/ISO 27001/ISMS 등은 회사 프로필에 명시된 경우에만 원문으로 쓴다.**
  회사 자료에 보안 인증이 없으면 `ISO 27001 취득`, `보안 인증 취득` 같은 계획도 작성하지
  않고 `보안/배포 요구사항은 제출 전 확인`만 사용한다.
- **공식 공고/양식에 지원 규모가 없으면 금액을 추측하지 않는다.** `최대 1억 원` 같은
  대표 금액도 실시간 공식 출처나 양식 원문이 없으면 쓰지 않는다.
- **회사 프로필에 없는 고객/파일럿 수는 절대 새로 만들지 않는다.** 예시 문서의
  `5개사 PoC`, `3곳 파일럿`, `10개사 고객`은 형식용이며, 사용자 회사의 파일럿 고객 수를
  늘리거나 바꾸는 근거가 되지 않는다. 회사 프로필에 `파일럿 고객: 2개 물류사`가 있으면
  `2개 물류사`로 그대로 쓰고, `파일럿 고객 5개사`처럼 재조합하지 않는다.
- **회사 프로필에 없는 매출/예산/인력 목표는 쓰지 않는다.** `매출 1억 원 예상`,
  `개발자 2명 추가 채용`, `보증한도 50억 원` 같은 일반 상식 수치도 사용자 회사 자료나
  공식 공고에 없으면 본문에 넣지 않는다.

## 3. 정규화 카테고리 (원문 예시어 반복 금지 시 사용)

사용자가 근거 없음으로 준 원문 예시어는 아래 카테고리명으로만 정규화한다.

- `고객/파일럿 근거` — 파일럿 고객, 초기 고객사, 계약, PoC 관련 예시
- `시장/수요 자료` — 시장 규모, 성장률, 고객 세그먼트 관련 예시
- `성과 측정 기준` — 정확도, 처리 시간, KPI, 매출 목표 관련 예시
- `대표/팀 근거` — 대표 경력, 팀 구성, 역할, 채용 계획 관련 예시
- `보안/배포 요구사항` — 온프레미스, 보안 인증, 배포 형태 관련 예시. 확인 질문에서도
  구체 용어를 예시로 들지 않고 이 카테고리명으로만 묻는다.
- `예산/자금 운용` — 비목, 금액, 지원금 사용 계획 관련 예시

## 4. 안전 템플릿 문장

아래 문장은 근거가 없는 항목에 대해 우선 사용한다. 새 숫자나 예시를 덧붙이지 않는다.

- 고객/수요: "주요 고객은 사용자 회사 제품/서비스가 해결하는 업무를 겪는
  조직이다. 시장/수요 자료는 공신력 있는 자료 확인 후 확정한다."
- 실행계획: "제품 고도화, 공식 공고/필요 서류 정리, 파일럿 설계 순서로
  진행한다. 고객/파일럿 목표는 근거 자료 확인 후 확정한다."
- 예산/인력: "지원금 활용 세부 산정이 필요하다. 현재 임직원 수는 회사 프로필(RAG)
  기준이며 직묳별 구성과 채용 계획은 제출 전 확인 필요하다."
- 성과지표: "제품 품질, 처리 시간, 고객/파일럿, 매출 목표는 측정 기준과 근거
  자료 확인 후 확정한다."
- 보안/배포: "보안/배포 요구사항은 제출 전 확인한다."

## 5. 사용처

- `apm.yml`의 `artifact_quality_checks.forbidden_patterns`는 이 목록의 `금지 예시`
  열을 regex로 구현한다.
- `apm.yml`의 `artifact_quality_checks.rewrite_patterns`는 이 목록의 `금지 예시`를
  `정규화 표현`으로 rewrite한다.
- `agent.md`와 `SKILL.md`는 이 목록을 참조하되, 개별 regex를 반복하지 않는다.
- 최종 QC는 이 목록에 없는 새로운 근거 없는 수치/주장이 추가되지 않았는지 확인한다.

## 5. 최종 출력 전 반드시 확인할 항목

아래 표현이 본문에 남아 있으면 QC가 실패한다.

- 금지: `최대 N억 원`, `N억 원`, `매출 N억 원 달성` (공식 공고/양식 원문에 없을 때)
  - 허용: `지원 규모는 공식 공고 확인 후 확정`
- 금지: `파일럿 고객 N개사`, `고객 N개사`, `파일럿 N개사 확대`
  - 허용: 회사 프로필 원문 형태 그대로, 예: `2개 물류사`, 또는 `고객/파일럿 목표는 영업 파이프라인과 근거 자료 확인 후 확정`
- 금지: `개발자 N명`, `영업 N명`, `개발 N명`, `기획/영업 N명`
  - 허용: `채용 계획은 예산안과 역할 정의 후 확정`
- 금지: `보안/배포 요구사항은 제출 전 확인합니다. (온프레미스/클라우드 선호도, 보안 인증 여부 등)`
  - 허용: `보안/배포 요구사항은 제출 전 확인`
- 금지: `온프레미스/클라우드 선호도가 있나요?`
  - 허용: `보안/배포 요구사항은 제출 전 확인입니다. 관련 기준을 준비해 주세요.`
