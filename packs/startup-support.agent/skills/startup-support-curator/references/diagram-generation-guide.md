# 사업계획서 다이어그램 생성 가이드

이 레퍼런스는 startup-support APM이 5-0~5-4 각 하위 절에 남기는 `도식 초안`을
구체화하는 방법을 정리한다. 이 APM의 HTML 아티팩트는 `visual_assets_enabled: false`,
`diagram_style: preformatted` 설정을 따륯므로, 기본 출력은 브라우저에서 바로 읽을 수
있는 텍스트 도식 초안이다. Mermaid/SVG/Excalidraw는 별도 visual asset 파이프라인이
연결된 경우에만 선택적으로 사용한다.

## 1. 도식 생성 원칙

- **한 절에 하나의 핵심 도식**: 5-0~5-4 각 하위 절마다 최소 하나의 표 또는 도식을
  포함한다. 둘 이상 필요하면 복합 도식으로 합치거나 보조 표로 분리한다.
- **고객 언어 라벨**: 노드와 축 라벨은 내부 구현명이 아니라 고객/사업/평가항목
  언어로 쓴다.
- **근거 연결**: 각 노드 옆에 `공고 근거` 또는 `회사 근거`를 짧게 표기한다.
- **출력 형식 우선순위**:
  1. HTML 아티팩트 내 `<pre>`/`<table>` 텍스트 도식 초안 (기본)
  2. Mermaid 다이어그램 (`<pre class="mermaid">`로 감싸기, 지원되는 렌더러에서만)
  3. HTML `<svg>` (별도 차트 생성 능력이 연결된 경우에만)
  4. Excalidraw JSON (사용자가 별도로 편집할 때만 첨부)

## 2. 섹션별 도식 매핑

### 5-0 사업개요 요약

**핵심 도식: 이해관계자 가치 흐름**

```
[기관/지원사업]
      │ 공고·자금·네트워크
      ▼
[자사 스타트업] ──문서/업무 자동화 서비스──► [중소기업·스타트업]
      │                                              │
      │◄──────────── 운영 효율·검토 품질 개선 ────────┘
      │
      └──────► [기관/지원사업] 성과보고·후속연계
```

**대안: 제품 파이프라인**

```
[공고/회사 자료 수집]
      │
      ▼
[OCR·RAG·구조 파싱]
      │
      ▼
[적합도 매칭]
      │
      ▼
[사업계획서 초안]
      │
      ├──────► [HTML 아티팩트]
      └──────► [캘린더/알림 후보]
```

### 5-1 문제인식

**핵심 도식: 문제 3분할 카드**

```
┌─────────────────┬─────────────────┬─────────────────┐
│ 자료 산재       │ 출처 불명확     │ 운영 부담       │
├─────────────────┼─────────────────┼─────────────────┤
│ 여러 채널의     │ 원본/버전 관리  │ 수작업 검토     │
│ 공고/양식을     │ 어려움          │ 시간이 길어짐   │
│ 수작업으로 모음 │                 │                 │
└─────────────────┴─────────────────┴─────────────────┘
```

**대안: 직접 구축 vs 제품 사용 비교**

| 항목 | 직접 구축 | Schift Agent Hub 사용 |
| --- | --- | --- |
| 초기 인력 | 전담 개발팀 필요 | 기존 팀으로 운영 |
| 공고 모니터링 | 수작업/스프레드시트 | 자동 수집·정규화 |
| 사업계획서 초안 | 문서별 재작성 | 공고 평가항목 기반 초안 |
| 유지보수 | 낮은 커스텀 코드 | 플랫폼 업데이트 |

## 3. Mermaid 활용 (선택적)

Mermaid는 플로우차트, 간트차트, 시퀀스 다이어그램에 적합하다. 단, HTML 아티팩트에서
Mermaid를 렌더링하려면 런타임에 Mermaid 라이브러리가 로드되어 있어야 한다. 기본
설정(preformatted)에서는 `<pre>`/`<table>` 텍스트 도식을 우선 사용한다.

- 노드 라벨은 고객/사업 언어로 쓴다.
- 화살표 방향은 실제 흐름과 일치해야 한다.
- 복잡한 다이어그램은 서브그래프로 그룹핑한다.

## 4. SVG/차트 활용 (선택적)

별도 visual asset 파이프라인이 연결된 경우에만 아래 차트를 생성할 수 있다.

- **TAM/SAM/SOM**: 막대 차트, 근거 없는 시장 수치는 `확인 필요`로 표기.
- **Gantt**: 협약기간 월별 과제를 Mermaid gantt 또는 SVG rect로 표현.
- **누적 막대 로드맵**: 연도별 성과 구분을 SVG rect stack으로 표현.

모든 차트는 HTML `<svg>`로 self-contained 되어야 하며, 외부 라이브러리 의존 없이
브라우저에서 렌더링되어야 한다.

## 5. 출력 계약

- 도식 초안은 HWP/PDF로 옮길 수 있을 만큼 구체적이어야 한다.
- 노드/라벨/축/화살표/표 셀은 모두 텍스트로 편집 가능해야 한다.
- 이 APM의 기본 출력은 HTML 아티팩트 내 `<pre>`/`<table>` 텍스트 도식이다.
- Mermaid/SVG/Excalidraw는 별도 visual asset 파이프라인 연결 시에만 사용한다.
- 최종 QC에서 도식 라벨에 내부 구현명이 보이면 HOLD다.
