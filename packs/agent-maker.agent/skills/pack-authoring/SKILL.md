# Pack Authoring

## 언제 쓰나
"~해주는 에이전트/봇이 필요하다", "이 업무를 자동화하고 싶다" 같은 요청.

## 절차

1. **중복 확인.** 카탈로그에서 유사 팩을 먼저 찾는다. 있으면 사용자에게 알리고
   진행 여부를 확인한다.
2. **범위 좁히기.** 사용자가 말한 것이 여러 일이면 쪼갠다. 각각이 독립적으로
   쓸모 있는지 확인하고, 무엇을 먼저 만들지 정한다.
3. **모르는 것 묻기.** 아래가 안 정해졌으면 지어내지 말고 묻는다.
   - 누가 쓰나(조직 내부 / 고객 대면)
   - 입력이 무엇이고 결과가 무엇인가
   - 산출물이 필요한가, 답만 하면 되나
   - 실패하면 어떻게 하길 원하나
4. **초안 작성.** 세 파일을 쓴다. `agent.md`에 **금지 사항**과 **실패 시 행동**을
   반드시 포함한다.
5. **검토 요청.** 초안을 보여주고 무엇을 가정했는지 명시한다. 발행은 하지 않는다.

## 자주 하는 실수 (피할 것)

- **금지 사항 없이 능력만 나열** → 모델이 범위를 넘어 지어낸다.
- **도구를 잔뜩 선언** → 조직마다 다르게 줄 수 없게 된다. 최소한만.
- **"전문가처럼", "최고의" 같은 형용사** → 판단 기준이 아니다. 구체적 규칙을 쓴다.
- **실패 경로 누락** → 자료가 없을 때 무엇을 할지 안 적으면 그럴듯하게 채운다.
- 같은 일을 하는 팩이 이미 있는데 새로 만들기.

## 산출 형식

```
apm.yml        선언 (name/version/skills/tools/visibility)
agent.md       인격 + 판단 기준 + 금지 사항 + 실패 시 행동
skills/<n>/SKILL.md   절차 + 실패 처리 + 금지
```

각 파일이 왜 그렇게 됐는지 한 줄씩 설명을 붙여 사용자가 검토할 수 있게 한다.
