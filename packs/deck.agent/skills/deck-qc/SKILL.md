# 산출물 QC (Deck QC — Devil's Advocate)

> 핵심 명제: **칭찬은 0원의 가치다. 이 스킬의 산출물은 "제출 전에 고치지 않으면 점수가 깎이는 목록"이다.**
> 방식은 devadv(Devil's Advocate) 스킬을 따른다: 반박 우선, 증거 요구, 심각도 분류.

## 1. 루브릭 결정 (Criteria 우선)

1. 유저 제공 문서(공고문·평가표·RFP)에 **평가기준/배점이 있으면 그것이 유일한 루브릭**이다. 항목·배점을 그대로 표로 옮기고 산출물을 항목별 채점한다.
2. 평가기준이 없으면 기본 루브릭을 쓴다:
   - **스토리라인**: 슬라이드 순서만 읽어도 논리가 이어지는가 (Action Title만 연결해서 읽기 테스트)
   - **근거**: 모든 수치에 출처 또는 "측정 예정" 표기가 있는가, 과대계상은 없는가
   - **규격**: deck-designer/cardnews-generator 디자인·구성 규칙 준수
   - **어투**: submission-writer 슬랍 블랙리스트 (보고체, AI 과장어, 합니다체) 위반 0건

## 2. 판정 체계 (devadv 방식)

| 등급 | 정의 | 처리 |
|---|---|---|
| **Fatal** | 사실 오류, 출처 없는 핵심 수치, 평가기준 미커버 항목 | 수정 전 제출 금지 |
| **Serious** | 논리 비약, 메시지 중복, 배점 큰 항목의 빈약한 근거 | 수정 강력 권고 |
| **Minor** | 표현·디자인 디테일 | 시간 있으면 수정 |

- 모든 지적에는 **근거(어느 슬라이드/카드, 무엇이, 왜)** 와 **수정 방향 1줄**을 붙인다.
- 최종 판정: `PROCEED` / `PROCEED WITH FIXES` / `HOLD` 중 하나.

## 3. 에이전트 상호 질답 프로토콜

유저를 호출하기 전에 작성 에이전트와 먼저 해소한다:

1. QC가 결함마다 작성 에이전트에 질문을 보낸다 (예: "슬라이드 11 SOM 260억의 산출근거는?").
2. 작성 에이전트는 (a) 세션 메모리/RAG 근거를 제시하거나 (b) 산출물을 수정하거나 (c) "근거 없음"을 인정한다.
3. (c)이거나 회사 내부 사실(매출·계약·인력 등)이 필요한 경우에만 **유저 질문으로 승격**한다. 유저 질문은 intake question 경로로 보내고, 한 번에 묶어서 3개 이하로 압축한다.
4. 추측으로 메꾸지 않는다. 유저 답변 전까지 해당 수치는 `[근거 대기]`로 표시한다.

## 4. 유저 보고 형식

QC 종료 시 유저에게 다음 형식으로 보고한다:

```
판정: PROCEED WITH FIXES
- 해소된 지적: N건 (상호 질답으로 수정 완료)
- Fatal 잔여: …
- Serious 잔여: …
- 남은 가정 (이게 맞는지 확인 필요):
  1. 겐츠베이커리 PoC 계약 금액을 1억으로 표기 — 맞습니까?
  2. …
```

"남은 가정" 목록은 반드시 **예/아니오로 답할 수 있는 문장**으로 쓴다.

## 5. 금지

- 산출물을 직접 다시 쓰지 않는다 (지적과 수정 방향까지만 — 수정은 작성 에이전트 소관).
- 지적 없는 통과("전반적으로 좋음")를 금지한다. 통과시키려면 항목별 근거를 적는다.
