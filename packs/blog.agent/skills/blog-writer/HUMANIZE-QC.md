# 블로그 휴머나이즈 QC (Blog Humanize QC)

> 출처: Humanize KR (github.com/epoko77-ai/im-not-ai). 목적은 "검열"이 아니라 "사람이 쓴 글로 되돌리기".

## 판정 절차

1. **AI-tell 스캔** — 아래 패턴을 본문에서 찾는다. 발견 시 심각도와 위치를 기록한다.
   - S1(반드시 수정): "결론적으로", "시사하는 바가 크다", "~의 중요성이 대두", "~를 통해" 남발, "최고의/완벽한/혁신적" 등 과장.
   - S2(수정 권장): 기계적 병렬("첫째/둘째/셋째"), 접속사 문단 시작 반복, 수동태 남발.
   - S3(가벼움): 이모지·em-dash 과다, 문장 길이 균일.

2. **사실성 체크** — 수강료·합격률·후기 수·기간 등 모든 수치가 회사 메모리에 근거 있는지 확인한다. 근거 없으면 삭제하거나 "문의 시 안내" 같은 가드로 바꾼다.

3. **surgical 수정** — 발견된 구간만 고친다. 의미·사실·고유명사·숫자는 바꾸지 않는다.

4. **과편집 가드** — 원고 대비 변경이 30%를 넘으면 경고하고, 50%를 넘으면 멈춘 뒤 유저에게 알린다. 글의 장르(블로그 구어체)를 보고체로 바꾸지 않는다.

## 출력

- `grade`: A~D (남은 AI-tell + 과편집 신호 기준).
- `findings`: [{severity, span, fix}] 목록.
- `unresolved`: 회사 메모리에 없어 유저 확인이 필요한 수치/사실.
- `revised_html`: 수정 반영본.
