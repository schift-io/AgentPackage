# imgs2vid Constraints

모델 라우팅·길이·비용 확인과 리트라이 가드레일. 정적 문서보다 인증된 Higgsfield MCP가
현재 반환하는 도구 스키마와 비용 preflight를 우선한다.

## 공식 CLI 모델 ID와 계획 역할

| model ID | 계획 역할 | 기본 길이 | 실행 계약 |
|---|---|---:|---|
| `seedance_2_0` | 기본 | 5초 | 인증된 `tools/list.inputSchema`가 허용 필드·값의 정본 |
| `kling3_0` | 대안 비교 | 서버 스키마 확인 | 같은 CLI ID라도 MCP 도구별 스키마를 다시 확인 |
| `minimax_hailuo` | 대안 비교 | 서버 스키마 확인 | 같은 CLI ID라도 MCP 도구별 스키마를 다시 확인 |
| `veo3_1` | 품질 우선 후보 | 서버 스키마 확인 | 같은 CLI ID라도 MCP 도구별 스키마를 다시 확인 |

이 ID들은 공식 CLI에서 확인된 값이다. MCP가 특정 도구에서 동일한 `model` 필드나 같은
duration/aspect/audio 옵션을 제공한다고 미리 가정하지 않는다.

## 길이 가드레일

- `seedance_2_0`의 계획 기본값은 5초다.
- Schift는 편집 리듬과 승인 단위를 작게 유지하기 위해 클립을 2~6초로 제한한다. 이 범위는
  Higgsfield나 개별 모델의 최대·최소 길이를 뜻하지 않는다.
- 실행 시 서버 스키마가 요청 길이를 허용하는지 확인한다. 허용하지 않으면 호출하지 않고
  샷 분할 또는 모델 변경안을 다시 승인받는다.

## MCP 계약

- 엔드포인트는 `https://mcp.higgsfield.ai/mcp`, transport는 OAuth Streamable HTTP다.
- 런타임은 OAuth 토큰으로 `tools/list`를 호출하고, 반환된 각 도구의 `inputSchema`를 그대로 노출한다.
- 정적 문서에 생성 도구명이나 공통 인자 세트를 고정하지 않는다. `start_image`를 포함해 실제
  필드명·required·enum은 실행 시 받은 스키마와 일치해야 한다.
- 인물 일관성은 Soul에서 `reference_id`를 만든 뒤 Soul-aware 이미지 생성에 적용한다. 승인된
  패널 결과가 비디오의 `start_image`가 된다. 모든 비디오 도구에 통용되는 캐릭터 학습 도구나
  캐릭터 참조 필드는 가정하지 않는다.

## 비용 가드레일

- 코드나 문서의 USD/초 값은 모델 비교와 승인 화면의 범위를 잡기 위한 **계획치**다.
- 생성 직전 Higgsfield 비용 preflight가 반환한 견적이 정본이다. 계획치와 다르면 최신 견적을
  보여주고 다시 승인받는다.
- 승인 전에는 이미지·비디오 유료 생성 호출을 하지 않는다. `tools/list`, 스키마 검증, 로컬 계획만 허용한다.

## 리트라이 가드레일

- 클립당 최대 2회 리트라이를 계획하되, preflight 견적과 사용자의 승인 범위를 넘는 재시도는 하지 않는다.
- 동일 파라미터로 2회 연속 실패하면 루프를 멈추고 사용자에게 복구 선택지를 보여준다.
- identity drift가 반복되면 비디오에 임의 필드를 추가하지 않는다. 이미지 단계의 Soul reference와
  앵커를 보정하고 새 패널을 승인받은 뒤 다시 시도한다.
- 장면을 병렬 실행할 때도 승인된 패널 수와 비용 상한을 넘지 않도록 동시 실행 수를 제한한다.
