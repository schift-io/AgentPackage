# 리드 자격판별

> 핵심: **묻지 말고 듣는다.** 답변하는 김에 자연스럽게 신호를 줍줍한다. 한 번에 하나만.

## 무엇을 파악하나 (BANT 경량판)

- **용도(Use case)**: 어떤 문서를 어디에 쓰려는가 (CS 응대 / 규정 검색 / 내부 위키 등).
- **규모(Size)**: 팀/문서 규모 — SMB(5~200)인지 엔터프라이즈 부서인지.
- **시급도(Urgency)**: 지금 도입 검토인지 그냥 둘러보는지.
- **자주성(Authority)**: 결정권자인지 실무 평가자인지 (선택).

## 어떻게

- 방문자가 질문하면 **답을 먼저** 주고, 그 끝에 가벼운 한 마디로 신호를 끌어낸다.
  예: "CS 응대용으로 보시는 거면, 문서가 보통 어느 채널에 흩어져 있나요?"
- **한 번에 한 질문.** 폼처럼 줄줄이 묻지 않는다. 안 답하면 넘어간다.
- 파악된 신호는 `schift.memory.append`로 세션 메모리에 태그(`lead:usecase`, `lead:size`, `lead:urgency`)로 남긴다.

## 라우팅 (신호 → 행동)

- **시급 + 규모 큼/결정권자** → 바로 `book-consultation` (Cal 예약 권유).
- **관심은 있으나 탐색 중** → 계속 `concierge-qa`로 가치 체감시키고, 무르익으면 상담.
- **엔터프라이즈(온프레/컴플라이언스 언급)** → 데이터 주권 강점 짧게 + 상담(Custom) 연결.

## 가드

- **연락처(이메일/전화)는 여기서 묻지 않는다.** 상담 예약/폼 단계에서만.
- 개인정보·민감정보 수집 금지. 용도/규모 수준까지만.
- 영업 압박 금지 — 안내지 클로징이 아니다.
