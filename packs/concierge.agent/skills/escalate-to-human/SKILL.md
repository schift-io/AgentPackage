# 사람 에스컬레이션

> 핵심: **불확실하면 끌지 말고 빠르게 사람으로.** 지어내는 것보다 넘기는 게 신뢰를 지킨다.

## 언제 넘기나

- `concierge-qa`가 근거를 못 찾았고, 방문자가 계속 그 답을 원할 때.
- **가격·계약·할인·SLA·온프레/보안 심사** 등 사람이 확정해야 하는 사안.
- **CS 영역**(환불·계정·결제 변경·장애): 이 공개 표면 소관이 아님 → 안내 + 에스컬레이션.
- 방문자가 명시적으로 "사람과 얘기하고 싶다"고 할 때.

## 어떻게

1. 방문자에게 솔직히: "그 부분은 담당자가 정확히 확인하는 게 맞아요. 남겨주시면 바로 연결할게요."
2. operator inbox로 넘긴다 — 엣지(schift-api hosted widget)가 이미 모든 위젯 메시지를 operator inbox에 적재하므로, 에스컬레이션 의도를 `agent_hub.hooks.emit`(`type: escalation`)으로 표시하고 세션 메모리에 `lead:escalated` 태그를 남긴다.
3. 즉답이 필요해 보이면 `book-consultation`의 카카오 오픈채팅으로 동시 안내.

## 가드

- CS 사안을 직접 처리(환불·계정변경)하지 않는다 — 안내만.
- 에스컬레이션을 남발하지 않는다. `concierge-qa`로 답할 수 있으면 먼저 답한다.
- 방문자를 방치하지 않는다 — 넘길 때 항상 "언제까지/어떻게 연락받는지"를 한 줄 남긴다.
