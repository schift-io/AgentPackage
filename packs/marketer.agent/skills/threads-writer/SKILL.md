# 스레드(Threads) 글쓰기

> 핵심: **1/N으로 쪼개고, 1/N에서 멈추게 하고(개인 스토리 후킹), Before→After로 끌고, 마지막에 행동 1개.**

## 구조 — 단일 포스트가 아니라 멀티파트 스레드

- 긴 내용은 **1/N, 2/N으로 쪼갠다.** 각 파트 500자 이내, 한 파트 = 한 호흡.
- 인사이트·빌드로그·데모는 보통 3~5파트. 짧은 한 가지 생각이면 단일 포스트도 OK.
- 발행은 1/N 게시 후 "스레드에 추가"로 이어붙여 한 번에 올린다(작성기 UI가 안내).

## 1/N — 후킹 (가장 중요)

- **추상 요약 금지. 개인 경험·현장 스토리에서 출발한다.**
  예: "정부 지원사업 영수증 처리하다가 문득, 이거 자동화 해보자 하고 토큰을 부어봤습니다"
- 결론(숫자)을 먼저 던지고 **"근데 더 재밌는 건 따로 있었습니다"** 식으로 다음 파트로 당긴다.
- task가 뭔지 보여주는 이미지를 1/N에 붙이면 도달률↑.

## 2~N/N — Before → After

- **Before**: "그냥 했더니 이렇게 안 되더라"(실패·한계). 번호 리스트로 나열.
- **After**: "그래서 이렇게 바꿨더니 되더라"(해결). 번호 리스트 + 결과 이미지(차트 등).
- 한 줄에 한 생각, 줄바꿈으로 호흡을 끊는다. 번호(1. 2. 3.)·대시("–")·콜론(":") 적극.

## 마지막 파트 — 교훈 + CTA

- 한 줄 교훈 + 전체 글 링크 또는 행동 1개. 해시태그 0~1개.

## 말투

- **말투는 SOUL 페르소나를 따른다** (우선순위: 세션 `active_persona` > §4 활성 설정 > §3 채널 매핑).
- `catlovessubakba`(빌더) 페르소나면: **"~습니다/입니다" 격식체가 메인** + "~보죠/거죠/이에요" 구어 종결 + **나열 줄에만 음슴체("~됨/미끄러짐")를 부분적으로**. 음슴체"만"으로 쓰지 말 것.
- 추임새("근데....", "네.", "막")·말줄임("...!!!")·도발 비유 OK. 질문/단정으로 마무리.
- AI 티 금지: 번역체·AI 관용구·과장어·이모지 남발 금지. 본문 이모지 거의 없음.
- 숫자는 메모리 근거 있는 것만.

## 이미지

- **이미지는 항상 만들지 않는다. 필요할 때만.** 시각이 메시지를 실제로 강화할 때(후킹 1/N의 장면, After의 결과 차트)만 `generate_image`를 쓴다. 텍스트로 충분한 파트는 이미지 없이 둔다.
- 만들 땐 task 설명 이미지는 1/N, 결과 차트는 After 파트에 매핑.
- **size는 `1536x1024`(4:3 가로)가 기본** — 스레드는 가로로 긴 이미지가 도달률이 가장 좋다. 정사각이 꼭 필요할 때만 `1024x1024`.
- 프롬프트는 한국어 맥락을 유지하고, `brand_kit`에 고객 로고가 제공된 경우에만 로고 사용을 허용한다. 제공되지 않은 로고·URL·핸들은 지어내지 않는다. 실측 데이터가 있으면 차트는 수치를 반영.

## 출력 계약 — 텍스트만 낸다, HTML은 renderer가 만든다

- **LLM은 HTML을 직접 만들지 않는다.** 구조화 JSON만 낸다:
  ```json
  {
    "kind": "thread",
    "blog_url": "https://schift.io/blog/...",
    "parts": [
      {"n": 1, "total": 4, "label": "후킹·스토리",
       "text": "정부 지원사업 영수증 처리하다가 문득...",
       "images": [{"role": "task", "prompt": "...", "url": null}]},
      {"n": 2, "total": 4, "label": "Before", "text": "...", "images": []}
    ]
  }
  ```
- 각 `text`는 500자 이내, 파트당 한 호흡. `images[].role`은 `task`/`result` 등, `prompt`는 generate_image용, `url`은 생성 후 채워짐.
- **HTML 아티팩트는 `social` renderer가 고정 템플릿(스레드 작성기)에 이 JSON을 주입**해 만든다. 템플릿이 제공하는 것: 파트별 복사 버튼·글자수 카운터(500 초과 경고)·이미지 미리보기/저장/재생성 버튼·인라인 편집·발행 순서 안내.
- 이미지는 해당 파트 카드에 자동 매핑된다(role/순서 기준).
